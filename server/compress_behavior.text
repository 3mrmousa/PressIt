Compress Function Behavior (Step-by-Step)
========================================

When a user sends a request to compress an image (`POST /api/compress/compress`), the request passes through a sequence of middlewares and finally the controller. Here are the exact steps that happen, ignoring the commented-out history and cloud-upload features:

1. Authentication Check (`optionalProtect` middleware):
   - The server checks if an `access_token` cookie is present.
   - If a valid token exists, it verifies the JWT and attaches the corresponding user document to `req.user`.
   - If there is no token or it's invalid, it does not throw an error; it simply proceeds as a "guest" request.

2. Usage Limit Check (`checkCompressionLimit` middleware):
   - It identifies the requester using their User ID (if logged in) or their IP address (if guest).
   - It determines the user's tier (their subscription plan, "free", or "guest").
   - It constructs a Redis key specific to the user/IP, their tier, and the current date (e.g., `compress:guest:<ip>:2026-08-15`).
   - It increments the daily usage counter in Redis. If it's the first request of the day, it sets the counter to expire in 24 hours.
   - It checks this counter against the allowed `LIMITS` for their specific tier.
   - If the limit is exceeded, it immediately rejects the request with a `429 Too Many Requests` error ("Daily limit reached").

3. File Upload Processing (`uploadSingleImageForCompress` middleware):
   - Uses `multer` (with memory storage) to process the multipart/form-data request.
   - Looks for an uploaded file in the field named `compress-image`.
   - Validates the file:
     - The file size must not exceed 20MB.
     - The file type must be one of: `image/jpeg`, `image/jpg`, `image/png`, or `image/webp`.
   - If validation fails, it throws a `400 Bad Request` error.
   - If successful, the file's data is stored in memory (`req.file.buffer`).

4. Image Compression (`compressImage` controller):
   - Verifies that `req.file` exists.
   - Extracts the `percent` value from the request body (defaulting to 100 if not provided).
   - Validates that `percent` is a valid number between 1 and 99. Throws a 400 error if invalid.
   - Calculates the target file size in bytes: `originalSize * (1 - percent / 100)`.
   - Calls a utility function (`compressToTargetSize`) which uses the `sharp` library to compress the image buffer down to the calculated target size. (It also determines the output format based on the input type).
   - Prepares the HTTP response headers to provide metadata to the client:
     - `Content-Type` is set to `image/jpeg` (the current logic forces JPEG output).
     - `X-Original-Size` is set to the original byte size.
     - `X-Compressed-Size` is set to the new compressed byte size.
   - Finally, it sends the raw compressed image buffer back to the client directly in the response body.
